# Tiny API Hub — 边界与需求

本文是新仓的**唯一需求源**。实现前先读。

参考实现：同级目录 `../all-api-hub`（只读）。  
不要拷它的文件，不要改它的代码，不要 clone 它当本仓起点。

---

## 0. 怎么建这个仓库（硬约束）

| 规则 | 含义 |
| --- | --- |
| 复用旧仓代码 | 从旧仓 `all-api-hub` 复制**要保留功能的代码**：站点协议、UI 组件、设置页、壳层、样式、i18n。不是重写。 |
| 精简掉不要的功能 | 按**功能清单**只留勾选的功能。清单未勾的整块删（UI + 服务 + 菜单项 + 路由）。 |
| 旧仓冻结 | 不在 `all-api-hub` 里删功能、不改包、不切商店 ID。两仓独立。 |
| 位置 | `D:\Code\projects\tiny-api-hub`，与 `all-api-hub` 同级。 |

允许：

- 复制旧仓 `src/**` 实现文件（协议、UI、壳、样式、i18n、测试）到本仓 `src/**`
- 复制后按精简范围裁剪：删未勾选的 feature 目录、删对应 service、改菜单 / 设置 Tab / popup Tab 去掉入口
- 调整 extension id / 存储前缀，两仓可共存
- 修断裂 import、删依赖

禁止：

- 保留清单未勾的功能（网关、网页抓取、书签、用量图、公告、Kilo/Cursor++/CLIProxy/CCR、OpenRouter/AIHubMix/SharedChat、赞助、PostHog、导览、分享图、Safari、移动端、`unknown`/One API 兜底、今日现金流、LDOH、邀请链接、账号标签、用量快照等）

**与早期 clone+strip 的区别**：clone+strip 是整仓复制后做减法；现在是按目录/文件复制要留的，再删不要的。结果一样（精简版），手段从「全拷再删」改成「选拷」。两者可混用：大块整目录拷（壳、共用组件、要留的 feature），零碎的按需拷。

## 1. 产品是什么

浏览器扩展。管理少数中转站账号 + API 凭据：余额、密钥、模型、测通、签到、导出到常用客户端、本地/WebDAV 备份。

不是 All API Hub 精简包，是同问题的新实现。

---

## 2. 阶段 1（当前）

**目标：** 功能在本机浏览器可用。

- `pnpm dev`（或等价）跑起来
- Chrome / Edge / Firefox **加载未打包扩展**
- 不做商店上架、不申请商店扩展 ID、不提交审核
- 不做 Safari、不做移动端打包

阶段 1 完成 = 下列范围内的功能能在本机点着用，不是「能上架」。

---

## 3. 做（范围内）

来源：`all-api-hub` 规划清单勾选项，已核对冲突后的终版。

### 3.1 账号

- 添加 / 编辑 / 删除 / 启用禁用 / 置顶 / 拖拽排序 / 搜索 / 备注
- 筛选：启用状态、站点类型、刷新状态、签到状态
- 虚拟滚动长列表
- 余额（USD / CNY）、健康状态、上次同步时间
- 站点类型：仅 New API。添加时不检测其他品牌；非 New API 协议失败则添加失败，无 `unknown` 兜底
- 认证：Access Token、Cookie（含 Cookie 可选权限建议）
- 添加时自动填当前站点 URL、重复警告、去重对话框
- 从浏览器书签批量导入账号（不是「站点书签」产品）
- 添加失败恢复交接
- 添加时自动开通默认密钥
- 账号行：复制运行时密钥、跳转密钥/模型、打开**站点**用量页/兑换页（外链）、立即刷新、立即签到
- 排序优先级：禁用靠后、置顶、手动、当前站点、健康、待签到

### 3.2 凭据库

- Base URL + API Key 的 CRUD / 搜索
- 查余额、看模型、测连通
- 与账号密钥互相关联
- popup / sidepanel Tab + 设置页管理
- 导出到客户端（仅 3.6 三个目标）

### 3.3 密钥

- 按账号列出 Token / 运行时 Key / 服务凭证
- 搜索、新建（名称/额度/过期/IP/模型限制/分组）、一次性明文弹窗、编辑删除
- 修复缺失密钥、清理无效密钥
- 关联凭据库、验证 Key、单条导出

### 3.4 模型

- 按账号 / 跨账号汇总、跨站比价
- 计费模式、厂商标记、能力徽章、分组筛选、排序
- 详情展开、从模型跳到可用 Key、批量验证可用性

### 3.5 验证

- 协议：OpenAI Compatible、OpenAI Responses、Anthropic Messages、Google Gemini
- 流式 / 非流式
- 探测：`/models`、文本生成、工具调用、结构化输出、联网搜索
- 验证结果历史
- CLI 模拟：Claude Code、Codex、Gemini CLI（打协议，不真装 CLI）

### 3.6 导出

- CC Switch
- 导出协议：OpenAI Compatible / Responses / Anthropic / Gemini

（Cherry Studio、Kelivo 不做）

### 3.7 签到

- 全局开关、每账号意图、方法发现、手动覆盖、自定义 URL
- 立即全跑、定时调度、结果表（筛选/排序/分页/重试）、账号快照表
- popup 一键签到、打开外部签到页
- 完成后浏览器系统通知

### 3.8 站点（仅 New API）

| 站点 | 说明 |
| --- | --- |
| New API | 账号站 |

不做 AnyRouter、Done Hub、Sub2API。无 `unknown`、无 One API 品牌兜底。  
从备份导入时，其他 `siteType` → 拒绝并提示，不静默丢。

实现时对照旧仓 `NewApiFamily` 默认变体。**协议可参考旧仓，不要拷适配器目录。**

### 3.9 备份

- 本地导出：全部 / 仅账号 / 仅偏好
- 本地导入：文件 / 粘贴 JSON / 分段 / 合并策略  
  分段**不要**含：渠道配置、标签、书签
- WebDAV：手动上传下载、加密信封、定时同步
- 同步范围：账号、凭据库、偏好。**不含书签**
- 同步完成：浏览器通知

### 3.10 壳

- popup：账号 Tab + 凭据 Tab；余额统计卡；快捷入口（密钥/模型/签到）
- 工具栏点击：popup 或 sidepanel（不支持则回退 popup）
- 设置页：侧栏、折叠、移动端抽屉、设置内搜索
- 侧栏页面：总览、账号、凭据、模型、密钥、签到、基本设置、导入导出、关于
- 外观：亮/暗/跟随系统；语言 8 种（zh-CN / zh-TW / en / ja / vi / pt-BR / es-419 / de）
- 显示：货币 USD / CNY（无今日现金流、无余额/现金流 Tab 切换）
- 本地日志级别、可选权限页、重置设置、关于页
- 总览：指标、不健康账号、签到自动化状态、权限引导。无用量快照

### 3.11 平台能力（用户看不见，但要做）

- 临时窗口/临时页请求（过站点上下文限制）
- 防护绕过（Cloudflare / Turnstile / CAP 等），开关只挂：账号刷新、签到、密钥
- Cookie 拦截
- 后台 alarms：刷新、签到、WebDAV
- 账号 / 凭据 / 偏好存储

开发构建可做：Mesh Gradient Lab、Unified API 引导预览、过盾开发触发器。

### 3.12 通知

- 任务：自动签到、WebDAV 自动同步
- 渠道：仅浏览器系统通知  
  不做 Telegram / 飞书 / 钉钉 / 企业微信 / ntfy / 通用 Webhook

- 网页 AI API 检测、兑换码辅助、防护盾页面提示
- 站点书签产品
- 余额历史图表、用量分析、用量历史上游同步
- 站点公告聚合、扩展产品公告
- 导出：Kilo / Roo / Cursor++ / CLIProxy / Claude Code Router
- AnyRouter / Done Hub / Sub2API 专用接入
- OpenRouter / AIHubMix / SharedChat 专用接入
- 邀请链接、分享快照、账号标签、今日消费/收入、LDOH
- 赞助推荐、PostHog、产品导览、更新后弹更新日志
- Safari、移动端商店/打包
- 从旧仓「裁一刀当本仓」

## 5. 实现顺序（阶段 1）

不要平行铺全功能。垂直切片，每步本机能用。

1. **空仓脚手架**：WXT + React + TypeScript。能加载未打包扩展（popup 空白也行）
2. **账号**：添加 / 列表 / 刷新。先打通 **New API**
3. **密钥**：列出、新建、复制
4. **模型**：按账号列表、比价可后补
5. **凭据库**
6. **验证**（API 探测；CLI 模拟可后补）
7. **签到**（先手动立即跑，再定时）
8. **导出** CC Switch（Cherry / Kelivo 不做）
9. **本地导入导出** → **WebDAV**
10. popup/sidepanel 打磨、通知、过盾/临时页补齐（过盾按站点实际需要提前插入，不要拖到最后）

过盾和临时页：New API 刷新一旦在真实站点被拦，立刻补，不要等第 10 步。

## 6. 技术默认（可改，改前写进本文）

为方便对照旧仓协议，默认同一技术族，**代码仍全新**：

- 扩展框架：WXT
- UI：React + TypeScript
- 包管理：pnpm
- 测试：Vitest（按切片补，不为旧仓测试文件做移植）

存储、目录、状态管理允许与旧仓不同。优先更短、更少抽象。
